## بازطراحی بر اساس جهت بصری Figma

مرجع، پنج اسکرین‌شات دسکتاپِ Figma Make بود که کاربر همراه پیام فرستاد. تلاش برای بازکردن لینک Figma Make با Playwright انجام شد، اما صفحه بدون نشست احراز‌شده با 401 و پیام «Sign up to use Figma Make» متوقف شد؛ بنابراین تطبیق روی همان پنج تصویر انجام شده است، نه ادعای مشاهدهٔ تعاملی همهٔ حالت‌های Figma.

UI به سمت نقشهٔ تمام‌صفحه و پنل سمت راست حرکت کرد:

- تم تیرهٔ B-scoped با توکن‌های مستقل؛ صفحه‌های A و Base بدون کلاس B تغییر نمی‌کنند. تم پیش‌فرض B تیره است و با دکمهٔ نقشه به روشن/تیره تغییر می‌کند.
- در دسکتاپ، هدر Base پنهان و search/filters شناور روی نقشه قرار می‌گیرد؛ پنل راست با فاصله، گوشهٔ گرد و ارتفاع کامل. stepper اختصاصی B (انتخاب محصول / فروشگاه‌های نزدیک / مقایسه / تأیید و مراجعه) جای stepper کوچک Base را می‌گیرد.
- نقشهٔ تمام‌صفحه با فیلتر تیره روی همان کاشی OSM؛ پین‌ها به شکل برچسب قیمت، خوشهٔ شمارشی، کنترل‌های locate/theme/list و attribution آشکار در سمت چپ.
- کارت فروشندهٔ Figma-مانند: عنوان/فروشنده، قیمت، فاصلهٔ هوایی، ساعت/اعتبار، آدرس، شاهد پاساژ/طبقه/واحد، جزئیات بازشو و actions. دکمهٔ انتخاب و مقایسه در اولین بلوک دیدنی کارت است.
- CTA شناور مقایسه در پایین پنل (۲/۳ آفر) و هدر «فروشگاه‌های نزدیک» با «تغییر مدل» و sort سروری (کمترین قیمت/نزدیک‌ترین).
- سفر مراجعه با کارت‌های metric جایگزین ETA: فاصلهٔ هوایی، ساعت اعلامی و اعتبار اعلامی؛ سپس «داخل پاساژ» فقط وقتی شاهد متنی دارد.
- عناصر Figma که به داده/سرویس معتبر نیاز دارند و ساخته نشدند: زمان پیاده/ماشین، ETA، «به‌زودی بسته می‌شود»، نقشهٔ داخلی و تعداد مغازه‌ها. این‌ها عمداً با ادعای واقعی جایگزین نشدند.

## چه ساخته شد

### ۱. فروشندگان و انتخاب

- `StoresScreen` روی `useOffers` و `loadedOffers` مشترک؛ فیلتر/مرتب‌سازی/صفحه‌بندی سمت سرور.
- آفرها بر اساس `shop_id` فقط برای نمایش گروه می‌شوند؛ هر `offer_id` جدا و قابل انتخاب می‌ماند. کارت دوم یک فروشگاه با `offer_id` خودش به پیش‌نویس، مقایسه و برنامه می‌رود.
- شمار «آفر/فروشگاه بارگذاری‌شده» با برچسب مجموعهٔ همین شرایط و صفحه نمایش داده می‌شود؛ ادعای پوشش کل تهران یا آمار کل فروشگاه‌ها نیست.
- تغییر فیلتر/بودجه/موقعیت، انتخاب قبلی را حفظ می‌کند و `selectionNeedsReview` را با پیام و «تأیید همین انتخاب» نشان می‌دهد. انتخابِ خارج از نتیجهٔ بارگذاری‌شده قابل تأیید نیست و CTAها مسدود می‌شوند.
- صفحه‌بندی و retry حفظ ردیف‌های قبلی؛ خطای سرویس با حالت خالی یکی نیست.

### ۲. نقشهٔ واقعی

- Leaflet 1.9.4 و markercluster 1.5.3 با CSS محلی پکیج؛ بدون CDN و بدون dependency تازه.
- کاشی raster OSM با URL قابل‌تعویض `VITE_MAP_TILE_URL` و attribution آشکار؛ فقط کاشی‌های ناحیهٔ دیده‌شده و بدون پیش‌دانلود. اگر pin یا موقعیت نباشد، کاشی درخواست نمی‌شود.
- در تم تیرهٔ B، کاشی با فیلتر CSS تیره می‌شود تا به جهت Figma نزدیک شود؛ این یک فیلتر ظاهری روی OSM است، نه provider جدید.
- پین هر فروشگاه برچسب قیمت است و تمام `offerIds` را نگه می‌دارد؛ کلیک پین فقط فروشگاه را در فهرست برجسته/باز می‌کند و هیچ آفری را خودکار تأیید نمی‌کند.
- خوشه‌ها با رفتار استاندارد zoom/spiderfy؛ فروشگاه‌های هم‌مکان خوشه می‌شوند و بدون جعل مختصات، با زوم/spiderfy و نیز فهرست قابل دسترسی‌اند. خوشهٔ شامل انتخاب فعلی نشانه‌گذاری می‌شود.
- موقعیت انتخاب‌شده، دایرهٔ شعاع (خط‌چین قرمز) و خط هوایی فقط با مختصات معتبر؛ هیچ مسیر خیابانی/ETA/زمان پیاده‌روی ادعا نمی‌شود.
- `cameraIntent` (all/user/selection) تنها با اقدام صریح؛ framing اولیه یک‌بار و با padding پنل/جست‌وجو. حرکت دستی با تغییر پین‌ها یا انتخاب بازنویسی نمی‌شود.
- کنترل‌های نقشه: موقعیت من، تم روشن/تیره، نمایش فهرست در موبایل. دکمهٔ «نمایش روی نقشه» موبایل نقشه را آشکار و دوربین را روی انتخاب می‌برد.
- خطای کاشی با `role="alert"` و retry، بدون از کار انداختن فهرست؛ provider همچنان بدون SLA.

### ۳. مقایسهٔ آفرها

- مقایسهٔ ۲ تا ۳ آفر از همان محصول با جدول محلیِ اسکرول‌پذیر (بدون overflow کل صفحه)، سطرهای قیمت/فاصله/ساعت/اعتبار/آدرس/شواهد/اقدام و راهنمای اسکرول در موبایل.
- حذف/افزودن آفر از مقایسه؛ انتخاب غیررتبهٔ اول و «برنامهٔ مراجعه» از ستون دوم آزموده شد.
- `compareOffers` و `visitPlan` مستقل‌اند؛ صرف مقایسه برنامه نمی‌سازد و با یک فروشگاه هم مقصد ساخته می‌شود.

### ۴. پیگیری، نتیجه و جایگزین

- `useSellerFollowup`/`prepareFollowup` فقط پیش‌نویس ارسال‌نشده می‌سازد؛ هیچ شماره/tel/واتساپ/کانال تماس/ارسال واقعی وجود ندارد.
- نتیجه با source صریح `simulated` (پیش‌فرض) یا `user_report` و outcomeهای `no_answer|closed|out_of_stock`. متن صریح می‌گوید تأیید بیرونی/پاسخ فروشنده نیست؛ SimBadge دیده می‌شود.
- نتیجهٔ کامل و پیش‌نویس در `state.followups[offer_id]` می‌مانند؛ خروج/بازگشت آن‌ها را از بین نمی‌برد.
- جایگزین‌ها فقط از `findAlternatives` همان محصول؛ همهٔ آفرهای فروشگاه گزارش‌شده کنار می‌روند، excluded count و limitations نمایش داده می‌شود. `no_alternatives` صریح است و بودجه/شعاع خودکار افزایش نمی‌یابد.
- انتخاب جایگزین به‌عنوان مقصد، منبع simulated/user_report را در سفر نشان می‌دهد.

### ۵. برنامهٔ مراجعه

- مقصد اصلی + جایگزین اختیاری؛ آدرس، شاهد متنی پاساژ/طبقه/واحد (`addressEvidence` + `matchedText`)، قیمت تاریخی، زمان تغییر، موجودی تأییدنشده، ساعت اعلامی و اعتبار اعلامی مستقل.
- metricهای جایگزین ETA: فاصلهٔ هوایی، ساعت اعلامی، اعتبار اعلامی؛ «داخل پاساژ» فقط با شاهد متنی و با تصریح نبود نقشهٔ داخلی/تعداد مغازه.
- ساعت نامعلوم هرگز بسته معرفی نمی‌شود؛ `in_person_credit` تأیید اعتبار خریدار نیست.
- لینک بیرونی OpenStreetMap فقط با اقدام کاربر و مختصات معتبر؛ بدون clipboard/share/ETA. Back درون‌برنامه از `navigation` مشترک.

## محدودیت‌ها و موارد باز

- Figma Make بدون نشست احراز‌شده باز نشد (401/Sign up)؛ مرجع، پنج تصویر ارسالی بود. تطبیق تعاملی همهٔ狀態های Figma ادعا نمی‌شود.
- فقط Chromium headless آزموده شد؛ دستگاه واقعی iOS/Android، screen reader، Safari/Firefox و حرکت واقعی نقشه آزموده نشده‌اند.
- Back مرورگر در پوستهٔ مشترک پیاده نشده؛ Back درون‌برنامه آزموده شد.
- برای چیدمان تمام‌صفحه، B هدر/stepper/search پوسته را فقط روی صفحه‌های خودش با CSS بازچینش می‌کند؛ راه‌حل نهایی باید از یکپارچه‌سازی/Base بیاید.
- برای آشکارکردن نقشهٔ موبایل، B دکمهٔ sheet پوسته را از DOM کلیک می‌کند و برای نام پین از `loadedOffers` می‌خواند؛ هر دو در requests-B ثبت شد.
- جایگزین‌های بیش از صفحهٔ اول فقط با پیام `has_more` نمایش داده می‌شوند (API offset دارد).
- provider کاشی OSM بدون SLA؛ فیلتر تیره ظاهری است و کاشی روشن/تیرهٔ رسمی نیست.
- metricهای Figma برای پیاده/ماشین/ETA و وضعیت زندهٔ بسته‌شدن با دادهٔ فعلی ساخته نشدند؛ تعداد مغازه‌های پاساژ و نقشهٔ داخلی هم نداریم.
- مسیر کامل A→B با مدل واقعی، ادغام نهایی، دیپلوی و ویدئو انجام نشده است. این گزارش پذیرش کامل محصول نیست.

## اجرا

```powershell
# API از ریشه
$env:TOROB_ASSISTANT_ENABLED='0'
.\.venv\Scripts\python.exe -m uvicorn apps.api.main:app --host 127.0.0.1 --port 8000 --no-access-log

# در apps/web
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm run test:ui-base
node --test unit/ui-b/*.test.mjs
npm run dev   # http://127.0.0.1:5173/design.html
```

Playwright B با fixture و بدون مدل؛ برای snapshot واقعی `TOROB_DATABASE` را به DB محلی اشاره دهید. بررسی provider جداگانه و محدود انجام شد.
