# A — کشف و انتخاب محصول

از SHA نهایی Base روی `codex/ui-a-discovery` و checkout مستقل شروع کنید. `README.md` همین پوشه، AGENTS و وضعیت واقعی Git مرجع‌اند. تغییرات جدید main را با هماهنگی دریافت کنید؛ شروع از کامیت قدیمی یا فرض انجام‌شدن B ممنوع است.

## مالکیت

فقط `apps/web/src/app/screens/a/`، `apps/web/unit/ui-a/`، `apps/web/tests/ui-a/` و `docs/ui-base/{log-A,requests-A}.md`.
فایل ورودی `index.tsx` از قبل به registry وصل است؛ export نام `DiscoveryScreen` و props آن حفظ شوند. می‌توان داخل همین پوشه کامپوننت، CSS با prefix `ua-` و hook اختصاصی ساخت.
به base، map، screens/b، package/lockfile، API backend، تست‌های قدیمی و HANDOFF/TASKS/DECISIONS دست نزنید. نیاز مشترک را در requests-A ثبت کنید.

## خروجی

۱. خانه و ورودی نیاز؛ قبل از انتخاب محصول، نقشهٔ خالی بر کار غلبه نکند. جست‌وجوی مستقیم و گفت‌وگو دو راه همکاری‌کننده باشند، نه ویزارد اجباری.
۲. Decide: استفاده از `useAssistant` و `conversationInput`؛ ارسال فقط با submit صریح. `question_code` شناسه است و question متن نمایش؛ pending به‌عنوان شرط اجرا‌نشده دیده شود. تاریخچه با تغییر بودجه پاک نشود. وضعیت provider غیرفعال/سقف/خطا مستقل از نتیجهٔ خالی باشد.
۳. Results: محصول از API واقعی، نام/تصویر همان محصول، source specs و توضیح شواهد. `explanation.limitations` آرایه است و تماس/تناسب/موجودی را پنهان نکند. هیچ رنگ/سایز/کیفیت اجرا‌نشده را فیلتر اعمال‌شده نشان ندهید.
۴. مقایسهٔ ۲–۳ محصول با `compareProducts`؛ سقف انتخاب، toast در دید کاربر، تفاوت مشخصات بر اساس section/key و نمایش دادهٔ ناموجود. مقایسه اختیاری است.
۵. صفحه‌بندی محصول با حفظ بودجه، دستهٔ حذف‌شده، minimum باتری، sort و موقعیت. بازهٔ عمومی قیمت و قیمت شاهد nearest متفاوت‌اند؛ معنای هرکدام واضح بماند.
۶. انتخاب محصول: dispatch `product` و سپس navigate به `stores`. صفحهٔ فروشگاه را A پیاده نمی‌کند؛ mount point آمادهٔ B است.

## رفتار و پذیرش

- سلام/ابهام/تغییر کالا/بودجه از قرارداد host پیروی کنند؛ NLP یا فیلتر تازه در frontend نسازید.
- history نمایشی و state معتبر حفظ شوند؛ صرف نگه‌داشتن پنج پیام جای `need_state` را نمی‌گیرد.
- جست‌وجوی دستیِ موضوع جدید نباید query و state قبلی را بی‌صدا با هم ناسازگار کند؛ تصمیم مبدأ و تغییر زمینه قابل مشاهده باشد. برای نیاز به تغییر مشترک، درخواست ثبت کنید.
- loading با حفظ نتیجهٔ قبلی، empty، unknown، خطا، لغو، تلاش مجدد صریح و provider disabled بررسی شوند.
- نام/قیمت/اقدام محصول در دید اولیهٔ موبایل باشد؛ عکس بزرگ یا log، تصمیم اصلی را نپوشاند.
- widthهای 320/375/390/768/1024/1440/1920، مرز واقعی 959/960، کم‌ارتفاعی، زوم 200٪، RTL/LTR، Tab/Enter/Escape و reduced-motion.
- قیمت با رشته/BigInt؛ صفر با null متفاوت. تصویر نامعتبر placeholder؛ متن منبع فقط متن امن React.

تست‌ها با مدل غیرفعال یا route fixture مشخص اجرا شوند؛ هیچ درخواست واقعی مدل یا خواندن کلید لازم نیست. build، `test:ui-base`، واحدهای A و مرورگر A اجرا و نتیجهٔ واقعی در log-A ثبت شود. تصاویر و گزارش خام محلی بمانند. هیچ push/remote انجام نشود؛ گزارش فایل‌ها، محدودیت‌ها و کامیت منسجم با قالب پروژه تحویل شود.
