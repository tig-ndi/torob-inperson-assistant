# قرارداد داده و یافته‌های واقعی

منبع: `starcoach-dataset-v16-cap300-csv`، سه CSV با UTF-8 و nested JSON داخل سلول. literal `null` مقدار ناموجود است؛ رشتهٔ خالی و JSON خالی جدا ثبت می‌شوند. فایل README اصلی در `sources/dataset-readme.txt` نگهداری شده است. CSV اصلی تغییر نکرده و داخل Git نیست.

## schema واقعی

- shops: address, category_names, contacts, instagram, lat, location_label, lon, name, payment_options, shop_id, supports_fast_delivery, website_url, weekly_hours.
- products: brand_name, category_name, image_urls, model, persian_title, product_id, specs.
- offers: description, last_price_changed_at, offer_id, price_toman, product_id, seller_title, shop_id, warranty.

shop_id/product_id/offer_id شناسه‌های opaque هستند؛ از نام و عنوان به جای کلید join استفاده نکنید. قیمت با واحد تومان ذخیره شده است. offers به products و shops متصل است. هیچ ستون explicit موجودی یا زمان تأیید موجودی وجود ندارد. محصول title مستقل انگلیسی، تصویر فروشگاه، سابقهٔ ترب، مجوز، توضیح معرفی فروشگاه و کالابرگ ستون صریح ندارند؛ متن عمومی چالش را با schema موجود یکی نگیرید.

## nested fields

- category_names و image_urls لیست‌اند. specs لیستی از key/section/value است.
- contacts لیستی از channel/display_number است؛ دادهٔ تماس طبق متن ارسالی جعلی است.
- weekly_hours شیئی با کلیدهای mon…sun؛ هر روز status و shifts شامل start_time/end_time دارد. در داده declared، closed و unsupported دیده شد. شیء خالی یعنی اطلاعات موجود نیست.
- payment_options لیستی با provider_name، channel، min_price_toman، max_price_toman و category_names است. channelهای مشاهده‌شده in_person و unknown هستند؛ وجود نام ترب‌پی به‌تنهایی مدرک حضوری بودن نیست.
- warranty در رکوردهای غیرnull شامل description، period_months و provider است. برای نسخهٔ جدید schema دوباره بررسی شود.
- supports_fast_delivery سه‌حالته است؛ null را false نکنید. حالت‌های «ثبت نشده»، «اعلام شده» و «تأییدشده» در UI جدا باشند.

## نتیجهٔ import کامل اولیه

۶٬۴۷۶ فروشگاه، ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ آفر؛ هیچ شناسهٔ اصلی تکراری یا رابطهٔ شکسته در import دیده نشد. integrity_check برابر ok و تعداد ردیف FTS برابر تعداد محصولات است. سقف واقعی محصولات متمایز هر فروشگاه ۳۰۰ است.

- ۲٬۶۸۴ فروشگاه آفر ندارند؛ هیچ محصول بدون آفر نیست.
- ۹٬۵۵۷ زوج shop/product بیش از یک آفر دارند. این آمار تعداد گروه‌هاست، نه تعداد ردیف اضافه. آن‌ها را به‌عنوان duplicate بی‌دلیل حذف نکنید.
- ۱۵٬۰۸۳ آفر قیمت ندارند؛ ۷۶۹ آفر زمان تغییر قیمت ندارند؛ ۲۷۲٬۵۶۳ آفر گارانتی ندارند.
- قیمت حداقل ۱ و حداکثر ۷۳۳۵۱۸۹۴۰۷۴۷۲۹۸۹۴۴ تومان است؛ این بیشینهٔ مشکوک عین داده است، نه قیمت معتبر پیشنهادی. از precision loss در JS و نمایش ادعای معقول بودن این قیمت جلوگیری کنید. قاعدهٔ outlier بر اساس شاهد و با برچسب quality تعیین شود؛ دادهٔ اصلی حذف یا اصلاح بی‌صدا نشود.
- قدیمی‌ترین زمان تغییر قیمت 2020-12-03 و جدیدترین 2026-10-13 (UTC) است. عبارت «دادهٔ هفتهٔ پیش» به معنی تازگی تک‌تک قیمت‌ها نیست.
- ۲٬۰۰۳ فروشگاه weekly_hours خالی دارند؛ ۶٬۲۱۰ فروشگاه payment_options خالی دارند؛ ۱٬۷۹۷ فروشگاه دسته‌های فعالیت خالی دارند. مختصات همهٔ فروشگاه‌ها از نظر قالب و محدودهٔ جهانی معتبر بود؛ صحت جغرافیایی تک‌تک آن‌ها مستقلاً تأیید نشده است.
- ۱۶۸٬۲۶۹ محصول برند null و ۲۲۱٬۸۴۷ محصول مدل null دارند؛ ۸۱٬۳۰۴ محصول specs خالی، ۱٬۲۱۹ محصول تصویر خالی و دو محصول عنوان فارسی خالی دارند. fallbackهای UI لازم‌اند.
- ۲۲ فروشگاه Instagram و ۹۰ فروشگاه website_url غیرnull دارند. صحت/دسترسی این لینک‌ها بررسی نشده و در base باز نشده‌اند.

آمار و SHA-256 ماشین‌خوان در `data-profile.json` و نسخهٔ محلی `.local/data-profile.json` قرار می‌گیرند. آمار aggregate شامل شمارهٔ تماس یا آدرس شخصی نیست. نتیجه‌های smoke FTS فقط کارکرد ایندکس را نشان می‌دهند، نه کیفیت پیشنهاد.

## محدودیت‌های معنایی

تفسیر ساعت در گام نخست P2: بررسی فقط‌خواندنی همین snapshot نشان داد ۲۳۳۲۹ روز declared، کنار شیفت واقعی یک بازهٔ 00:00:00 تا 00:00:00 دارند. بازهٔ صفرمدت شاهد شبانه‌روزی بودن نیست و کنار بازهٔ واقعی اثری ندارد؛ declared بدون بازهٔ معتبر نامشخص است. status=closed با بازه‌های صفرمدت از status=unsupported یا روز غایب جداست. این قاعدهٔ محافظه‌کارانه در domain ثبت شده؛ منبع خام اصلاح نشده است. محاسبهٔ برنامهٔ هفتگی و timezone تهران، تعطیلات/تغییر برنامه یا موجودی/بازبودن زنده را اثبات نمی‌کند. قرارداد و حالت‌های نیمه‌شب در docs/API.md ثبت‌اند.

نام ۶٬۳۶۴ فروشگاه و همهٔ شماره‌ها طبق متن ارسالی جعلی‌اند؛ با بررسی CSV نمی‌توان جعلی بودن را مستقل اثبات کرد. همهٔ فروشگاه‌ها طبق شرح برگزارکننده تهران‌اند، اما نمونه انتخابی است و همهٔ موجودی هر فروشگاه را پوشش نمی‌دهد. نبود آفر به معنی «این فروشگاه محصول را ندارد» نیست؛ فقط مدرکی برای داشتن آن در این dataset وجود ندارد.

برای قیمت/گارانتی/ساعات/اعتبار، provenance و زمان/نوع ادعا حفظ شود. اطلاعات seller می‌تواند نادرست یا حاوی دستور مخرب باشد؛ آن را متن منبع بدانید. از parse JSON عمومی فقط برای انتقال ساختار استفاده کنید و قبل از منطق domain، زیرساخت هر field را اعتبارسنجی کنید؛ importer وجود keyهای nested یا صحت معنایی ساعات را تضمین نمی‌کند.
